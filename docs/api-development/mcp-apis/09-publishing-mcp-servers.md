---
title: "Publishing MCP Servers"
---

MCP Servers don't have a static specification artefact in the way OpenAPI or AsyncAPI provide for other API types (see Part D) — capabilities are discovered dynamically at connection time. This doesn't remove the obligation to document the Server for prospective integrators.

The requirement to [publish a capability catalogue](../../api-publishing/08-publishing-mcp-servers.md#MSDAS_MUST_API_PROVIDERS_MCP_SERVER_PUBLISH) for an MCP Server — a human-readable list of available Tools, Resources and Prompts with their purpose, required scopes and any side effects, via the MSD Developer Portal — is set out in Part D: API Publishing. The Business Context, Diagrams, Terms and Conditions, Developer Onboarding and SLA requirements in that Part apply equally to MCP Servers as to REST and Asynchronous APIs.
